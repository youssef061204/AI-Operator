# Final engineering report

STATUS: **READY FOR RESUME / PORTFOLIO**, scoped as a local developer-agent platform. Not a production isolation boundary or general autonomous desktop operator.

1. **Initially:** two disconnected stacks, an 18-action monolithic engine, template cognition, SQLite logging, web/Electron interfaces, no automated tests. Initial build/lint failed on broken dependency links.
2. **Biggest problems:** unauthenticated execution, caller-selected permissions, approval bypass, canceled work becoming successful, fake synthesized tools, unconfined writes, and critical dependency advisories. Safe baseline reproduction confirms the approval/cancellation bugs.
3. **Architecture:** replaced the supported core with typed runtime/provider/tool/permission/store interfaces; retained historical sources and useful presentation/build infrastructure. See ADR 001.
4. **Added/rebuilt:** observe/act/verify loop, seven validated tools, exact expiring approvals, guarded edits, persistent rollback, command cancellation, context bounds, transactional events, authenticated API, CLI and task console.
5. **Removed from supported execution:** template business pipelines, fake specialists/tool synthesis, browser/Lovable claims, unrestricted OS control, privileged desktop preload/IPC, and automatic execution-service startup. Historical sources remain archived in place.
6. **Tests:** 23 passed, zero failed, one standard-symlink test skipped due to Windows privileges; junction test passed. Browser E2E passed. CLI exercised against the API. Typechecks, ESLint, formatting, web/agent/shared builds and Windows Electron portable packaging passed. New CI workflow is provided but was not run remotely.
7. **Evaluation:** 42/42 deterministic cases passed; zero measured permission violations; 100% rollback assertions. These use scripted providers and real tools, not an LLM success-rate benchmark. Separately, live local Qwen fixed a bug and passed its test after recovering from one timeout.
8. **Performance:** final deterministic median task 79.60 ms, p95 359.88 ms; median runtime/store startup 5.80 ms. One live-model task took 70.29 seconds, including an initial timeout; 70.07 seconds were model calls. No before/after speedup claimed.
9. **Security:** loopback authentication/origin/host checks, server-owned risk, one-use approval digests, stale-file checks, symlink/junction/hardlink defenses, bounded output, environment scrubbing, process cleanup and database ownership lock. Production and full development dependency audits both reported zero advisories after upgrades.
10. **Limitations:** approved shell retains OS privileges; filesystem races and escaping daemons are not fully contained; rollback is file-scoped and not power-loss durable; stale crash locks require manual verification/removal; no cross-data-directory workspace lock, cross-project memory or general browser/desktop tools. Desktop viewer needs the running web/runtime services. Installer is unsigned. See security.md.
11. **Run:** `pnpm install --frozen-lockfile`; configure an installed Ollama model with `OPERATOR_MODEL`; run `pnpm dev`; connect at localhost:3000 using `.operator/api-token`. Full setup/compiled deployment commands are in README.md.
12. **Evaluate:** `pnpm test`, `pnpm test:browser` (after `pnpm exec playwright install chromium`), `pnpm evaluate`, and optional `pnpm test:live`. Verification: `pnpm lint`, `pnpm format:check`, `pnpm build`, `pnpm audit`.
13. **Git:** repository initialized for publication after the implementation and local verification. User data preserved. All 75 baseline source hashes matched the local backup; the path-preserving archive remains local under artifacts/baseline and is ignored by Git.
14. **Changed areas:** packages/agent/src/runtime, main/CLI/exports and retired server entry; agent tests; web task console; Electron main; package manifests/lockfile; setup/CI/browser configuration; examples; audit/security/architecture/evaluation documentation and machine-readable artifacts.
15. **Resume bullets:** typed bounded agent orchestration; deterministic permission/edit/rollback safety; reproducible real-tool evaluations separated from live-model results. Exact wording is in interview-guide.md.
16. **Ten interview questions and grounded answers:** see [interview-guide.md](interview-guide.md), covering architecture, loop, deterministic boundaries, approvals, sandbox limits, cancellation, rollback, persistence, evaluation and next improvements.
